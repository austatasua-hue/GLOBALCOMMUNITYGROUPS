Visual wireframe of the digital marketplace platform showing the admin panel structure, customer dashboard layout, and high-level system architecture. Use these diagrams as the blueprint for build and design reviews.

## System architecture

```mermaid
flowchart TB
    subgraph Client["Client Layer (Mobile + Desktop)"]
        Web[Web App - React/Vue]
        Mobile[Mobile Browser]
    end

    subgraph App["Application Layer"]
        API[REST / GraphQL API]
        Auth[Auth & Session Service]
        Webhooks[Webhook Dispatcher]
    end

    subgraph Data["Data Layer"]
        DB[(MySQL / PostgreSQL)]
        Cache[(Redis Cache)]
        Logs[(Audit & API Logs)]
    end

    subgraph External["External Providers"]
        SMS[SMS / Virtual Number APIs]
        Social[Social Media APIs]

    Web --> API
    Mobile --> API
    API --> Auth
    API --> DB
    API --> Cache
    API --> Webhooks
    API --> SMS
    API --> Social
    API --> Pay
    Webhooks --> Logs
```

## Purchase flow

```mermaid
sequenceDiagram
    participant U as User
    participant W as Web App
    participant A as API
    participant P as Payment Gateway
    participant X as Provider (SMS / Social)
    participant H as Webhook

    U->>W: Browse catalog, add to cart
    W->>A: Create order
    A->>P: Charge card / PayPal / crypto
    P-->>A: Payment confirmed
    A->>X: Provision number / boost service
    X-->>A: Resource issued
    A-->>W: Order complete + credentials
    A->>H: Fire "purchase.completed" webhook
```

## Technical stack

| Layer | Choice |
| --- | --- |
| Frontend | React (Next.js) or Vue (Nuxt) |
| Backend | Node.js (NestJS) or Laravel |
| Database | PostgreSQL or MySQL |
| Cache / Queue | Redis + BullMQ / Horizon |
| Payments | Stripe, PayPal, Coinbase Commerce |
| Providers | SMS / virtual number APIs, social media APIs |
| Hosting | Containerized (Docker) on AWS / GCP / Fly.io |
